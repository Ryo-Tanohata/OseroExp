# 解説に使う言語モデルについて（無料・規約違反なしで使う方法）

## 考え方：「読む」のはAI、言語モデルは「話す」だけ

このアプリでは、局面を**読む（強さ）**のと、それを**言葉にする（説明）**のを分けています。

| 役割 | 担当 | 備考 |
| --- | --- | --- |
| 手を読む・形勢を判断する | AlphaZero（自己対局で学習）／ αβ探索AI | 言語モデルはオセロが弱くても問題ない |
| 事実を整理する | `js/explain.js`（最善手か悪手か・隅・X打ち・着手可能数・確定石など） | 言語モデルなしで動く |
| 文章にする（実況） | 言語モデル | 上の「事実メモ」と AlphaZero の勝率・候補手・読み筋を渡し、言い換えてもらうだけ |

言語モデルに盤面を一から分析させると、小さなモデルは間違いを書きがちです。
このアプリでは計算済みの事実を渡し、「書かれていないことは推測で断定しない」と指示しているので、
**ChatGPT 3.5 程度（7〜8B クラスのオープンモデル）でも十分に実況できます**。
言語モデルを使わない場合でも、`explain.js` のテンプレート解説は常に表示されます。

## 学習させずに質を上げる工夫（プロンプト）

言語モデル自体は学習させず、毎回のプロンプトで振る舞いを整えています（文脈内学習）。

| 工夫 | 場所 | 効果 |
| --- | --- | --- |
| システムプロンプト（役割・文体・「与えた事実以外は断定しない」） | `js/claude.js` | 口調をそろえ、でたらめを減らす |
| 事実メモ（手の良し悪し・隅・着手可能数・形勢など） | `js/explain.js` → `js/claude.js` | 分析は計算済みなので、モデルは言い換えるだけでよい |
| AlphaZero の勝率・候補手・読み筋 | `js/claude.js` | 数値の裏づけのある実況になる |
| **オセロの知識メモ** | `js/prompts.js` | 隅・X打ち・中割りなどの用語を正しく使う |
| **お手本の実況（3例）** | `js/prompts.js` | 長さ・口調・根拠の示し方をまねる（小さなモデルほど効果大） |
| 温度 0.3（ばらつきを抑える） | ブリッジ経由で送信 | 事実から外れにくくなる |
| 読み込める長さを 8192 トークンに拡大（Ollama） | `server/claude-bridge.mjs` | 既定の 2048 だとお手本入りのプロンプトの先頭が切れるため |

`js/prompts.js` のお手本と知識メモは自由に書き換えられます。
好みの実況の口調があれば、お手本を自分の文章に差し替えるのが一番効きます
（お手本は2〜4例が目安。多すぎると小さなモデルでは入りきりません）。

## 選べる方法

**既定は「内蔵の実況」**です。言語モデルを使わず、解説エンジンの計算結果と AlphaZero の読みから実況の文章を組み立てます。
インストール・ダウンロード・費用はいっさい不要で、公開ページ（GitHub Pages）でもそのまま動きます。
以下の言語モデルは、より自然な文章にしたい場合の**任意の追加**です。

| 方法 | 費用 | 必要なもの | 規約面 |
| --- | --- | --- | --- |
| **Ollama でオープンモデル**（おすすめ） | 無料 | メモリ 8GB 以上のパソコン（GPU があると速い） | 各モデルのライセンスに従えばOK。完全にオフラインで動く |
| LM Studio など（OpenAI 互換のローカルサーバー） | 無料 | 同上 | 同上 |
| ローカルの Claude Code | サブスクの利用枠内 | Claude Code（Pro/Max など） | 自分のパソコンで自分が使う分には、公式に用意された使い方（`claude -p`） |

### Ollama の使い方

```bash
# 1. https://ollama.com からインストール
# 2. モデルを入れる（例。日本語が比較的得意なもの）
ollama pull qwen2.5:7b        # 約5GB。Apache 2.0 ライセンス
#   パソコンが非力なら小さいモデル:  ollama pull qwen2.5:3b / gemma3:4b
# 3. ブリッジを起動してブラウザで開く
node server/claude-bridge.mjs   # → http://localhost:8787
# 4. 「言語モデル（Claude・実況）の設定」で「Ollama」を選び、「接続テスト」
```

モデルの目安（4bit 量子化版。Ollama の既定）:

| 大きさ | 例 | 必要メモリ目安 | 実況の質 |
| --- | --- | --- | --- |
| 3〜4B | `qwen2.5:3b`, `gemma3:4b` | 4GB 前後 | 簡単な実況なら可 |
| 7〜8B | `qwen2.5:7b`, `qwen3:8b`, `llama3.1:8b` | 6〜8GB | ChatGPT 3.5 前後。おすすめ |
| 12〜14B | `gemma3:12b`, `qwen2.5:14b` | 10〜16GB | より自然な日本語 |

GPU がなくても CPU だけで動きますが、1秒に数文字〜十数文字程度になります。
その場合は「実況が終わってから次の手へ進む」をオンにしておくと、実況を最後まで読めます。

## 規約違反を避けるために気をつけること

一般的な注意点です（最新の規約は各サービス・各モデルの公式ページで確認してください）。

1. **Claude や ChatGPT の出力で、自分の言語モデルを学習させない**
   Anthropic・OpenAI の利用規約は、出力を使って競合するモデルを開発することを禁じています。
   「Claude に解説を大量に書かせて、それで小さなモデルを学習させる」はやめましょう。
2. **サブスクリプションのアカウントを他人に使わせない**
   このアプリを公開して、他の人があなたの Claude Code 経由で使える状態にするのは避けてください。
   他の人に配るなら、各自が自分のアカウントを使うか、Ollama などのオープンモデルを使う形にします。
3. **Web のチャット画面を自動操作（スクレイピング）しない**
   このアプリは公式のコマンドラインツール（Claude Code）か、ローカルのモデルだけを使います。
4. **オープンモデルはライセンスを確認する**
   Qwen の多くは Apache 2.0、Gemma は Gemma 利用規約（禁止用途あり）、Llama は Llama ライセンス（表示義務や利用規定あり）です。
   個人でオセロの実況に使う分には、いずれも通常問題になりません。

## 将来、自分で小さな解説モデルを作りたくなったら

学習データには、**自分で作った文章**（`explain.js` のテンプレート解説など）や、
**ライセンスで出力の再利用が認められているオープンモデル**の出力を使うのが安全です。
ただし、上の表の 7〜8B のモデルを使うだけで実用上は十分なので、まずはそちらをおすすめします。
